## 監査ログ（AuditLog.meta）の読み方

このアプリでは、アップロード／再インデックス時の取り込み処理（抽出→チャンク化→Embedding→FAISS反映）の結果を **AuditLog.meta（JSON）** に残します。  
目的は、**「どのエンジンで抽出されたか」「品質劣化（文字化け・画像PDF疑い）が起きていないか」「なぜ失敗したのか」** を後から説明できるようにすることです。

---

### 1. 最初に見る項目（運用での一次確認）

#### `filename` / `file_path` / `file_ext`
- **確認意図**：どのファイルを処理したログかを特定するため。
- **読み方**
  - `filename`：アップロード元のファイル名（失敗時でも残る）
  - `file_path`：ストレージ上の保存パス（成功時に残りやすい）
  - `file_ext`：拡張子（Extractor選択が正しいかの確認にも使用）

#### `chunk_count`（成功時）
- **確認意図**：チャンクが生成され、DBへ保存できたかの確認。
- **注意点**
  - `chunk_count` は抽出品質の絶対指標ではありません（改行や分割境界の違いで増減します）。
  - ただし **極端に少ない／ゼロ** は抽出または分割の問題の可能性があります。

#### `error`（失敗時）
- **確認意図**：処理失敗理由の一次情報。
- **例**
  - `スキャンPDF（OCR未対応）の可能性が高いため取り込み不可です。`
    - 本アプリでは **画像PDF（テキスト抽出不可）は対象外** として明示的に弾きます（OCRは未実装）。

---

### 2. 抽出の要約（品質とフォールバックの結果を素早く判断する）

#### `extract_engine`
- **確認意図**：最終的にどの抽出エンジンを採用したかを確認するため。
- **値の例**
  - `pypdf2`：PyPDF2で採用（通常のテキストPDFで多い）
  - `pymupdf`：PyMuPDFで採用（文字化け／抽出品質低下時にフォールバックで採用されやすい）
  - `text`：TXT/Markdown抽出
  - `csv`：CSV抽出

#### `extract_warnings`
- **確認意図**：抽出品質の劣化が疑われるかを一覧で確認するため。
- **運用上の読み方**
  - `[]`：品質判定上は問題なし（ヒューリスティック検知なし）
  - 何か入っている：要注意（原因特定は `extract_meta` / `fallback.metrics` へ）

代表的な warnings と意味：
- `mojibake_suspected`：文字化け疑い（制御文字比率や日本語比率等のヒューリスティック）
- `pypdf2_advanced_encoding_unimplemented`：PyPDF2が高度エンコーディング未実装の警告（文字化けの根拠）
- `replacement_characters_many`：置換文字 `�` が多い（抽出不全の兆候）
- `image_pdf_suspected`：空ページ率が高い（スキャンPDF疑い）
- `no_text_extracted`：抽出テキストが空（OCRなしではRAG化できない）
- `low_text_volume`：抽出文字量が少ない（弱いシグナル。単独で失敗とは限らない）

---

### 3. 抽出詳細（根拠データ：extract_meta）

#### `extract_meta`
- **確認意図**：抽出処理の根拠（エンジン、警告、比較指標、PDFメタ等）を詳細に残すため。
- `extract_engine` / `extract_warnings` はここから抜粋して上位に持ち上げています。

主な内部キー：

#### `extract_meta.type`
- **確認意図**：抽出対象の種別（PDF / text / csv）を確認するため。
- 例：`pdf`, `text`, `csv`

#### `extract_meta.engine` / `extract_meta.warnings`
- **確認意図**：抽出エンジン／品質警告を詳細側でも保持するため（上位の `extract_engine` / `extract_warnings` と同義）。

#### `extract_meta.fallback`
- **確認意図**：PDF抽出でフォールバック（PyPDF2→PyMuPDF）が発生したか、なぜ切り替えたかを追跡するため。
- 内部キー：
  - `fallback.from`：最初に試したエンジン（通常 `pypdf2`）
  - `fallback.to`：最終採用エンジン（`pymupdf` なら切り替え成功）
  - `fallback.trigger_warnings`：フォールバックの引き金になった警告（pypdf2結果に付いたもの）
  - `fallback.metrics`：各エンジン結果の品質メトリクス比較（下記）

#### `extract_meta.fallback.metrics`
- **確認意図**：「なぜそのエンジンが採用されたか」を定量的に説明できるようにするため。
- 例：`metrics.pypdf2` と `metrics.pymupdf` の比較

代表的なメトリクス：
- `len`：抽出文字数（ゼロ検知や大差比較の参考）
- `replacement_ratio`：置換文字 `�` の比率
- `c1_ratio`：C1制御文字（0x80–0x9F）の比率（文字化けの強いシグナル）
- `latin1_ratio`：Latin-1領域（0xA0–0xFF）の比率（補助シグナル）
- `jp_ratio`：日本語文字（ひらがな/カタカナ/漢字等）の比率（日本語資料前提の妥当性チェック）
- `empty_page_ratio`：空ページ率（画像PDF疑いの根拠）
- `warnings`：そのエンジン結果に付いた warnings

---

### 4. PDF固有情報（原因推定に使う）

#### `extract_meta.pdf_meta`
- **確認意図**：PDF内部メタ情報から生成元や資料性質を推定するため。
- 例：`creator` が Photoshop 系 → 画像変換PDFの可能性が高い

#### `extract_meta.pypdf2_pdfread_warnings`
- **確認意図**：PyPDF2が出した PdfReadWarning を監査に残し、文字化けや抽出差分の根拠にするため。
- 例：`Advanced encoding ... not implemented yet`  
  → `pypdf2_advanced_encoding_unimplemented` の根拠

---

### 5. ログ例の読み方（典型3パターン）

#### (A) 正常PDF（問題なし）
- `extract_engine: pypdf2`
- `extract_warnings: []`
- `chunk_count` が正の値  
→ そのままRAG対象として問題なし

#### (B) 文字化けPDF（フォールバックで改善）
- `fallback.trigger_warnings` に `mojibake_suspected` 等が入る
- 最終的に `extract_engine: pymupdf`
- `extract_warnings: []` になれば改善成功  
→ PyMuPDF採用で日本語比率（jp_ratio）が上がるなど、`metrics` が根拠になる

#### (C) 画像PDF（対象外として弾く / OCR未実装）
- `error` が「スキャンPDF（OCR未対応）なので取り込み不可」
- `extract_warnings` に `no_text_extracted` / `image_pdf_suspected`
- `metrics.*.len == 0` や `empty_page_ratio == 1.0` が根拠  
→ OCR導入までは対象外（仕様）

---

### 6. 運用ルール（本アプリの前提）
- OCRは未実装（拡張余地として設計コメントのみ）
- スキャンPDF（画像のみ／画像主体でテキスト抽出不能）は対象外として ingest を失敗扱いにします
- 失敗時は `error` と `extract_warnings` を見れば、原因と方針（対象外・改善余地）が判断できます
